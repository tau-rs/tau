# ADR-0071: The three-surface split — TOML vocabulary, TypeScript choreography, Rust muscle

**Status:** Accepted (records locked decisions §10.2/§10.5 of the
[2026-09-01 consolidated design](../superpowers/specs/2026-09-01-tau-authoring-ops-and-primitives-design.md);
Phase 0 ADR wave)
**Date:** 2026-09-01
**Deciders:** maintainer, via the 2026-09-01 brainstorm session
**Supersedes:** parts of ADR-0002 (the `[steps]` / `[tools] native=`
vocabulary placement) and parts of ADR-0041 (see its banner)
**Amended by this ADR:** ROADMAP "killed items" (argued narrowing),
[`tau-philosophy.md`](../explanation/tau-philosophy.md) §"What you author"

## Context

A tau project today can be authored through four overlapping surfaces:
`tau.toml` (including `[steps]` pipelines and `[tools] native=`
references), `[dirs]`-scanned agent/tool files (ADR-0069), the
`tau-ts-extract` static TS factories (ADR-0041), and a TOML-emitting
Python SDK. The same fact — "this agent exists, with this model and these
tools" — can be declared in any of them, and the surfaces compete rather
than compose: TS factories re-express the whole TOML schema, TOML grows
flow constructs (`[steps]`) that strain a pure-data format, and native
tool identity lives as a bare string (`native = "ReadTemp"`) hashed by
name, not content (`crates/tau-cli/src/cmd/build.rs:533,597`).

The 2026-09-01 brainstorm resolved this with one assignment rule: **each
category of primitive has exactly one natural surface**, and one
declaration per fact.

## Decision

| Surface | Role | Contains |
|---|---|---|
| **TOML / dirs** | the vocabulary | agents (markdown + frontmatter under `agents/`), models, `[allow]` (**never emittable by code**), MCP tool contracts, triggers, context pipelines. Pure data — no templating, expressions, or includes, ever (the Helm-cycle rule). |
| **TypeScript** | the choreography | `pipelines/` — one file = one pipeline, id = file path ([dirs]-style scanning per ADR-0069/0070). Flow only: never prompts, models, tools, or capabilities. |
| **Rust** | the muscle | `#[tau::tool]`, `#[tau::deterministic]` + explicit `tau::export![]`. Name, schema, description, and capabilities derive from the signature + attribute. |

Concretely:

1. **`[allow]` is TOML-only forever.** The constitution is never
   generated by the thing it governs (design §1 rationale; G-level
   principle behind ADR-0057). No code path — synth, macro, or SDK — may
   emit or widen it.
2. **`[steps]` and `[tools] native=` are removed from TOML**, with a
   deprecate-warn cycle (one release warning, then rejection). Flow moves
   to `pipelines/*.ts`; native tool identity moves to the Rust attribute
   registry (real content hashes replace name hashes — the E-1 epic).
3. **TOML stays pure data.** No templating, expressions, or includes,
   ever — systems that added them (Helm) ended up with a
   string-templating language nobody can validate; the escape valve for
   logic is the TS surface at synth time, not TOML.
4. **TS is choreography-only and synth-time-only.** It never defines
   prompts, models, tools, or capabilities, and it never runs at runtime
   — the engine stays 100% Rust. The runtime-JS / QuickJS path
   (ROADMAP δ.2) is killed outright.
5. **Agents and models are TOML-dirs-only** (ADR-0069 scanning). The
   `pipelines/` directory joins the reserved-dirs set.

The mechanism by which TS reaches the validator is the synth contract —
ADR-0072. The multi-pipeline IR shape it produces is ADR-0073.

## Consequences

- One declaration per fact; `tau check` diagnostics can name the one
  surface a fact lives on.
- The legacy lanes lose their reason to exist: `tau-ts-extract` static
  factories and the TOML-emitting Python SDK are deleted in Phase 1
  (E-1), `tau-workflow` in Phase 0 (E-0). The one-validation-path
  pattern they proved carries forward (ADR-0072).
- `ROADMAP.md`'s killed item "authoring agents/workflows in Python or
  TypeScript as canonical source" is **narrowed by argument, never
  silently**: upheld for the vocabulary, lifted for choreography (the
  compiler thesis is preserved — TS emits config through the single
  validator and never runs at runtime).
- `tau-philosophy.md` §"What you author" must drop "TS is sugar over the
  IR": the surfaces are complementary by category, not interchangeable
  front-ends of one schema.
- Obligations created: deprecate-warn implementation for `[steps]` /
  `native=` (E-2); `pipelines/` reserved-kind comment update in
  `crates/tau-pkg/src/project/dirs/`; doc amendments listed above (E-0).

## Alternatives considered

- **TS defines everything (the CDK model).** Rejected: the constitution
  would be generated by the program it governs; capability review in CI
  becomes review of arbitrary code output, and one fact gains N
  authoring spellings. The CDK ecosystem's drift between "what the code
  says" and "what got synthesized" is the scar.
- **TOML grows expressions/templating instead of a TS surface.**
  Rejected on the Helm cycle: config formats that grow logic converge on
  an unvalidatable string-templating language. Flow needs a real
  type-checked language.
- **Keep three interchangeable front-ends (β.8's "one way to write a
  project, TOML or TS").** Rejected: N surfaces × M facts = N×M
  declarations to keep coherent, and the conformance matrix (byte-equal
  IR for every pair) grows quadratically while adding no expressive
  power.
- **Keep `[steps]` alongside `pipelines/` indefinitely.** Rejected: two
  flow surfaces is exactly the one-fact-two-declarations disease this
  ADR removes; the degenerate single `[pipeline]` case remains
  representable in the IR (ADR-0073) without a second authoring surface.
