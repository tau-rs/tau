# EPIC 4.2 — control-flow interpreter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `tau-runtime-core`'s pipeline interpreter *execute* the EPIC 4.1 control-flow blocks (`Branch`/`Parallel`/`Loop`), resolve the deferred nested-scope model in the `tau-ir-lower` typecheck, and replace the 4.1 stubs with two named errors.

**Architecture:** Extract the flat step-execution loop from `run_pipeline` into one recursive `run_steps` that top-level and nested bodies both call (flat global output namespace, execution-order visibility). `Branch` picks an arm; `Loop` is a bounded walk that hard-errors on exhaustion and threads feedback; `Parallel` is nginx-style bounded cooperative fork-join (`futures_util::buffered(8)`, index-ordered merge). `Suspend` aborts loudly (round-trip is 4.3). The typecheck gains tree-wide id uniqueness, the `Loop.until`-reads-body fix, parallel-branch isolation, and nested-template ref-checking.

**Tech Stack:** Rust, `no_std` + `alloc` (`tau-runtime-core`), `futures-util` (alloc), `serde_json`, `tracing`, `tokio`-driven integration tests with a bespoke `EchoBackend`/`MockLlmBackend`.

**Spec:** `docs/superpowers/specs/2026-07-18-epic-4.2-control-flow-interpreter-design.md`

    module: Arc<IrModule>,
    input: String,
    dispatcher: Arc<D>,

```rust
async fn run_steps<D>(
    module: &Arc<IrModule>,
    steps: &[PipelineStep],
    input: &str,
    store: &mut OutputStore,
    dispatcher: &Arc<D>,
    initial_feedback: Option<String>,
) -> Result<(), RuntimeError>
where
    D: ToolDispatcher + Send + Sync + 'static,
{
    use alloc::collections::BTreeMap;
    let mut attempts: BTreeMap<String, u32> = BTreeMap::new();
    let mut feedback: Option<String> = initial_feedback;
    let gate_index: BTreeMap<&str, usize> = steps
        .iter()
        .enumerate()
        .map(|(idx, step)| (step.id.0.as_str(), idx))
        .collect();
    let mut i = 0;
    while i < steps.len() {
        let step = &steps[i];
        // ... MOVED BODY: check dispatch, leaf dispatch, store.insert, i += 1 ...
    }
    Ok(())
}
```

Inside the moved body, replace `input` (the old owned `String` param) references with the `input: &str` param, and `store.insert(step.id.0.clone(), output);` stays. The `Ok(store)` return moves to the wrapper.

if let StepRun::Loop { body, until, max_iters } = &step.run {
    let mut loop_feedback: Option<String> = None;
    let mut converged = false;
    for _iter in 0..*max_iters {
        Box::pin(run_steps(
            module, body, input, store, dispatcher, loop_feedback.take(),

        if verdict.met {
            converged = true;
            break;

            step: step.id.0.clone(),
            max_iters: *max_iters,
        });
    }
    i += 1;
    continue;
}

```rust
if let StepRun::Parallel { branches } = &step.run {
    use futures_util::stream::{self, StreamExt};
    // Each branch forks a read-only snapshot; reads are branch-isolated,
    // so branches only ADD keys. Collect (index, produced_store).
    let futs = branches.iter().enumerate().map(|(idx, branch)| {
        let module = module.clone();
        let dispatcher = dispatcher.clone();
        let input = input.to_string();
        let mut snap = store.clone();
        async move {
            run_steps(&module, branch, &input, &mut snap, &dispatcher, None).await?;
            Ok::<(usize, OutputStore), RuntimeError>((idx, snap))
        }
    });
    let mut results: alloc::vec::Vec<(usize, OutputStore)> =
        stream::iter(futs).buffered(PARALLEL_CAP)
            .collect::<alloc::vec::Vec<_>>()
            .await
            .into_iter()
            .collect::<Result<_, _>>()?;
    // `buffered` preserves input order, but sort by index defensively so
    // the merge is deterministic regardless of driver scheduling.
    results.sort_by_key(|(idx, _)| *idx);
    for (_, produced) in results {
        store.merge(produced);
    }
    i += 1;
    continue;
}
```

Note: each branch clones the **pre-fork** `store`, so a branch cannot see sibling-branch outputs (matches the typecheck isolation rule in Task 7). The merge folds every branch's produced keys back.

- [ ] **Step 1: Write ADR-0059**

Use `docs/decisions/template.md`. Title: *IR control-flow interpreter semantics*. Status **Accepted**, Date 2026-07-18. Context: 4.1 shipped inert blocks + deferred nested-scope. Decision, recording all four choices verbatim from the spec:
1. **Flat global output namespace + execution-order visibility** (bare-id refs; `Loop.until` sees body; `Branch.on` sees outer-only; `Parallel` branch isolation). Resolves ADR-0058's deferred nested-scope note.
2. **`Parallel` = bounded cooperative fork-join** (nginx event-loop model; `futures_util::buffered(8)`; index-ordered snapshot/merge; no `Spawn` port / no `Send` sweep — executor-agnostic preserved).
3. **`Loop` = own bounded walk**, hard-error on exhaustion (`LoopExhausted`), `until`-failure feedback threaded into the next iteration; shares only the condition-eval + feedback primitives with `Check` gate-rewind.
4. **`Suspend` aborts** with `SuspendNotImplemented` — round-trip is EPIC 4.3.
Consequences: interpreter runs Branch/Parallel/Loop; no `ir_format` bump; a `Spawn` port is the deliberate future seam for compute-heavy `Dynamic` regions (4.4+). Alternatives considered: hierarchical/pathed scope; block-encapsulated outputs; sequential Parallel; `Spawn`-port true parallelism; loop stop-and-continue — all rejected with the spec's reasons.
