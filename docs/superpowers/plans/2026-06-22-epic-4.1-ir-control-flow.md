# EPIC 4.1 — IR structured control-flow blocks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Branch/Parallel/Loop/Suspend structured-control-flow variants to the workflow IR's `StepRun` (recursive), byte-stable when unused, build-time-typechecked, with the published IR JSON schema regenerated at `ir_format` v2.4.0 — the IR *data model* only (no interpreter).

**Architecture:** Append four variants to `tau-ir`'s `StepRun` enum (holding nested `Vec<PipelineStep>`), extract a reusable `Condition { evaluates: Locus, predicate: GoalPredicate }` from `CheckVerify::Goal`, recurse the `tau-ir-lower` typecheck into nested steps, bump `ir_format`, and regenerate the published schema (#430). Pure-serde canonical encoding makes appended variants byte-stable for existing IR.

**Tech Stack:** Rust (`tau-ir` no_std + alloc; `tau-ir-lower` std), serde/serde_json, schemars (schema feature), `cargo xtask gen-ir-schema`, `jsonschema` (conformance).

Spec: [`docs/superpowers/specs/2026-06-22-epic-4.1-ir-control-flow-design.md`](../specs/2026-06-22-epic-4.1-ir-control-flow-design.md).

In `typecheck.rs`, the step-reference validation currently matches `StepRun::Agent/Tool/Deterministic/Check` (lines ~175–178) and collects ids / checks `Locus::Output` per top-level step. Refactor the per-step validation into a function that, for the structured variants, recurses into the nested `Vec<PipelineStep>`:
```rust
fn validate_step_run(run: &StepRun, wf: &Workflow, /* + scope ctx */) -> Result<(), TypecheckError> {
    match run {
        StepRun::Agent(a) => require(wf.agents.contains_key(a), ...),
        StepRun::Tool(t) => require(wf.tools.contains_key(t), ...),
        StepRun::Deterministic(s) => require(wf.steps.contains_key(s), ...),
        StepRun::Check(c) => require(wf.checks.contains_key(c), ...),
        StepRun::Branch { on, then, otherwise } => {
            validate_condition(on, wf)?;
            for st in then.iter().chain(otherwise) { validate_step_run(&st.run, wf)?; }
            Ok(())
        }
        StepRun::Parallel { branches } => {
            for b in branches { for st in b { validate_step_run(&st.run, wf)?; } }
            Ok(())
        }
        StepRun::Loop { body, until, max_iters } => {
            if *max_iters == 0 { return Err(/* "Loop.max_iters must be > 0" */); }
            validate_condition(until, wf)?;
            for st in body { validate_step_run(&st.run, wf)?; }
            Ok(())
        }
        StepRun::Suspend { .. } => Ok(()),
    }
}
```
Add `validate_condition` (validate `Condition.evaluates` if it is a `Locus::Output(id)` referencing an in-scope step — reuse the existing `Locus::Output` logic). Use the actual `TypecheckError` variants/constructors already in the file (read them; don't invent — if a precise variant is missing, add one mirroring the existing `UnknownNode`/ref-error shape). Keep the existing top-level loop but route each step's `run` through `validate_step_run`.

## Task 4: ADR-0058 + PR

**Files:** `docs/decisions/0058-ir-control-flow-blocks.md`, `docs/SUMMARY.md`

- [ ] **Step 1: Write ADR-0058** (use `docs/decisions/template.md`): *IR structured control-flow blocks.* Context (the flat-pipeline limitation; EPIC 4 goal). Decision: recursive `StepRun` with Branch/Parallel/Loop/Suspend; `Condition` reuses `Locus`+`GoalPredicate`; `Loop` reuses `OnFail::Retry` rewind + mandatory `max_iters`; `Suspend` reuses the ADR-0053 `per_tool_call` checkpoint; additive `ir_format` v2.4.0; `Eq` dropped from the pipeline subtree (it now transitively holds `GoalPredicate::SchemaValid(Value)`). Consequences: interpreter (4.2)/Suspend (4.3)/Dynamic (4.4) follow; the published schema bumps minor. Alternatives: flat goto-style steps (rejected — not structured/verifiable); a separate `ControlFlow` node type instead of extending `StepRun` (rejected — `PipelineStep.run` is the single execution point; one recursive enum keeps the interpreter uniform). Status **Accepted**. Add to `docs/SUMMARY.md` under `# Architecture decisions` after ADR-0056 (note: ADR-0057 is `#423`, may not be on main yet — if its SUMMARY line is absent, add 0058 after 0056; if present, after 0057).
