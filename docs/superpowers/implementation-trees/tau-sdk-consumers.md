# Implementation Tree — tau JS/TS SDK consumer surface

> ## ⚠️ THIS IS A LIVING DOCUMENT
>
> This tree is **alive**. It is not a one-time snapshot — it is the running map
> of how a `tau build wasm` component reaches JavaScript/TypeScript hosts, and
> it **must be updated after every implementation** that touches this surface.
>
> Each slice you build teaches something the tree didn't know yet (a jco quirk,
> a bundler flag, a transport constraint). **Fold those discoveries back in the
> same PR that makes them** — update the affected node's status/PR, add to the
> Discoveries log with a date, and promote/retire items in "Next slices."
> A stale tree is worse than none: it reads as "this is how it works" when it no
> longer does.
>
> **Update protocol (do all four in the implementing PR):**
> 1. Flip the node's status marker and stamp its PR number.
> 2. Add a dated bullet to **Discoveries** for anything non-obvious you learned.
> 3. Move any now-built item out of **Next slices**; add any newly-revealed work in.
> 4. If a node's public surface changed, update its row in **Nodes**.

**Scope:** the JS/TS consumer path only — the wasm→JS transport, `@tau/embed-js`
host glue, the framework consumers, and the demo. It deliberately does **not**
cover the authoring SDKs (`@tau/sdk`, `tau-sdk-codegen` TS/Python emitters — see
[EPIC 5.3]) except where they share the `tau-sdk-codegen` crate as the emitter.

**Sibling docs:** design spec `docs/superpowers/specs/2026-08-08-epic-5-4-typed-consumers-design.md`;
roadmap `docs/superpowers/plans/vision-roadmap.md` (EPIC 5).

**Invariants (don't break without a deliberate slice):**
- Consumers take a `TauComponent`, never `loadTau`/wasm/jco — insulated from how the component was loaded.
- The guest exports **one prompt-only agent**; `text`/`events` describe exactly one stream. Multi-agent is a separate `TraceEvent` path.
- `@tau/embed-js` is **emitter-owned**: never hand-edit `sdk/embed-js/**`; edit `embed_js.rs` and regenerate (or `embed_js_drift` fails).
- Packages ship `.ts` **source** as the entry (no build step); consumers depend via `file:` (no JS workspace in-repo).

## Discoveries (append-only, dated)

- **2026-08-08/09** jco reality (F1, #552): `"jco":"^1"` is a dependency-confusion placeholder → `@bytecodealliance/jco@^1.27`; `$npm_config_wasm` is empty under npm 7+ → pass the wasm via `--`; needs `jco transpile --instantiation async --name component`; runtime import key is the **unversioned** `tau:host/host` (jco's `.d.ts` types it `@0.1.0`); `complete` is a **sync** WIT import (`(req)=>string`), live async needs `--async-mode jspi`.
- **2026-08-10** `RunEvent`/`RunOutcome` were imported but **not re-exported** from `index.ts` — every consumer needs them named. Fixed in #554.
- **2026-08-10** The `.ts` entry couldn't `tsc` because `index.ts`/`worker.ts` import the gitignored jco artifact `./generated/component.js` (TS2307). Fixed with an **ambient `src/generated.d.ts` + triple-slash `/// <reference>`** so it loads into any program compiling the source. #554.
- **2026-08-10** Vite build failed with `Invalid value "iife" ... code-splitting` because Vite **statically** bundles embed-js's `new Worker(new URL("./worker.ts", import.meta.url))` even when the app only uses main-thread `loadTau`; the worker's dynamic jco import is code-split. Fix: `worker: { format: "es" }` in the app's `vite.config.ts` (+ `optimizeDeps.exclude` for the file: packages). #579.
- **2026-08-10** jco's `node:fs/promises` import is externalized by Vite for the browser — a **harmless warning**; the browser path uses `fetch`. Confirmed by a real in-browser render.
- **2026-08-10** A trivial cassette completion **does** emit a `TextDelta` (full stream: RunStarted → InferenceCallStarted → TextDelta → InferenceCallCompleted → TurnCompleted → RunCompleted), so `useTauRun.text` renders non-empty. Cassette response shape: `{"text":"…","tool_uses":[],"stop_reason":"EndTurn","usage":null}`.
- **2026-08-10** Angular's `@Injectable` (legacy) decorator needs `esbuild.tsconfigRaw.compilerOptions.experimentalDecorators` in `vitest.config.ts`; `@angular/core` imports fine under a plain vitest node env (no zone.js).
- **2026-08-10** Stacked-PR merge: a child branch never touching a sibling's files keeps them via 3-way merge even when a two-dot `git diff main branch` shows them "deleted" — trust `mergeStateStatus: CLEAN`, don't force-rebase.

## Next slices (ranked)

1. **jspi async `complete`** — `jco --async-mode jspi` build path so `complete` can await a real network LLM. Highest user value; today the sync path is cassette/preloaded only.
2. **Worker `complete` RPC bridge** — `MessageChannel` (or similar) so `loadTauInWorker` supports a real `complete` off the main thread. Currently it always throws.
3. **Multi-agent streaming** — ⛔ blocked by the guest single-agent limit (`guest.rs:106`); uses the `TraceEvent` vocab, not `RunEvent`. Needs a guest change first.
4. **More hosts** — Vue / Svelte / vanilla consumers over the same `@tau/embed-js` `TauComponent`. Thin, like react/angular.
