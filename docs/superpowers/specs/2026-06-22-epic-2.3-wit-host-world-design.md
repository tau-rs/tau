# EPIC 2.3 — lock the WIT host world (rename + ports↔WIT drift test) — design

**Date:** 2026-06-22
**Status:** Approved (brainstorm) — pending spec review
**Epic:** 2 — Lock the two contracts as public ABIs (constitutional; BLOCKS 3, 5; informs 4)
**Story:** 2.3 (generate the WIT host world from the ports — one source → no drift; freeze the
minimal surface)
**Anchors:** [ADR-0055](../../decisions/0055-tau-identity-two-contracts.md),
[ADR-0056](../../decisions/0056-contract-versioning-stability-surface.md). Pairs with the
2.2 IR-schema contract (merged #430).

## Problem

ADR-0055/0056 fix the **WIT host world** as tau's second public contract (the embedding
interface), versioned by the WIT package version, *"generated from the ports … never
hand-maintained,"* under the containment invariant **WIT ⊊ ports**. Today:

- The world is hand-authored at `wit/tau-run.wit` as `package tau:run@0.1.0` — but ADR-0056
  names the contract `package tau:host`. The name diverges from its own ADR.
- `wit-bindgen`/`wasmtime::component::bindgen` consume the WIT **WIT→Rust** (guest + host both
  `generate!` the `runner` world) — so WIT is the *source* today, and there is **no enforced
  link** keeping it in sync with the `tau-ports` traits it mirrors. A port could be renamed or
  re-signatured and the WIT contract would silently diverge.

The minimal surface is 3 host functions, mapping 1:1 to three ports:

| WIT `host` fn | port |
|---|---|
| `complete: func(request-json: string) -> result<string, string>` | `tau_ports::llm::LlmBackend::complete` |
| `now-millis: func() -> u64` | `tau_ports::time::Clock::now` |
| `next-u64: func() -> u64` | `tau_ports::random::RandomSource::next_u64` |

## Decision

Two decisions from the brainstorm:

1. **Mechanism = freeze + drift test (Option A), not a bespoke generator.** There is no
   off-the-shelf Rust-trait→WIT generator (wit-bindgen is WIT→Rust) and the surface is 3
   functions; a custom generator is disproportionate. The enforceable guarantee ADR-0056
   actually requires — *"the drift test enforces WIT ⊊ ports"* — is delivered by a test that
   pins the WIT host surface to the ports. "Generated from ports" is honored in spirit: the WIT
   is frozen and **cannot silently diverge** from the ports.
2. **Rename `tau:run` → `tau:host`** (keep `@0.1.0`; pre-stable β, ADR-0056's semver *semantics*
   apply but no bump is warranted for a rename). Cheap now (only in-repo guest/host consume it);
   honors the contract's own ADR.

## 1. Rename (behavior-neutral)

- `wit/tau-run.wit` → `wit/tau-host.wit`; `package tau:run@0.1.0;` → `package tau:host@0.1.0;`.
  `world runner` and `interface host` names are unchanged.
- Update consumers:
  - `crates/tau-wasm-host/src/lib.rs`: `bindgen!({ path: "../../wit/tau-run.wit", world: "runner" })`
    → `path: "../../wit/tau-host.wit"`; `use tau::run::host;` → `use tau::host::host;`.
  - `crates/tau-wasm-guest/src/guest.rs`: `generate!({ world: "runner", path: "../../wit" })`
    is dir-based (no path change); `pub(crate) use super::tau::run::host::*;` →
    `super::tau::host::host::*;`; fix the `tau::run::host` doc comments (also in `host_ports.rs`).
- **Acceptance:** `cargo build -p tau-wasm-host` and `cargo build -p tau-wasm-guest
  --target wasm32-wasip2 --release` clean; the existing `#[ignore]` guest-exec tests
  (`cargo nextest run -p tau-wasm-host --run-ignored all`) still pass — proving the rename is
  behavior-neutral.

## 2. The ports↔WIT drift test (the deliverable)

`crates/tau-ports/tests/wit_host_drift.rs` (std test; `wit-parser` dev-dependency — use the
version already transitively present via wit-bindgen/wasmtime to avoid a second copy). It:

1. **Frozen-surface check.** Load `wit/tau-host.wit` with `wit-parser`; resolve the `host`
   interface; assert it declares **exactly** the 3 functions `complete`/`now-millis`/`next-u64`,
   each with its expected param/return types (per the table above). A 4th host import, a removed
   function, or a changed signature fails the test → the minimal surface is frozen.
2. **Containment (WIT ⊊ ports) via compile-time port references.** The test names
   `tau_ports::llm::LlmBackend::complete`, `tau_ports::time::Clock::now`, and
   `tau_ports::random::RandomSource::next_u64` in type-checked positions (e.g. binding each as a
   function item / referencing the trait method), so renaming or removing any of the three ports
   **breaks the test's compilation** — making "every WIT host function has a backing port" a
   build-enforced invariant.
3. **Correspondence table.** An in-test constant documents each WIT function ↔ port mapping,
   including the **`now-millis: u64` ↔ `Clock::now() -> i64`** signedness mapping (both are
   "milliseconds since the Unix epoch"; the host adapter bridges `i64`→`u64`; epoch-ms is
   positive). This is **documented as the agreed mapping**, not changed — locking the contract is
   2.3's job; if the signedness split is later deemed a bug, that is a separate change to a port
   or the WIT, out of scope here.

## 3. Reference doc + CI

- `docs/reference/wit-host-world.md`: the embedding contract — the 3 host functions, the
  `runner` world, versioned by `tau:host@0.1.0`, the WIT ⊊ ports relationship, and how the drift
  test enforces it. Mirrors 2.2's `docs/reference/ir-json-schema.md`. Add to `docs/SUMMARY.md`
  under `# Reference`.
- CI: add `cargo test -p tau-ports --test wit_host_drift` to the existing `conformance` job
  (alongside the 2.2 schema drift/conformance steps).

## 4. Scope guards

Lock + drift-test the **existing** 3-function embedding contract. **Out:** new host functions,
any wit-bindgen/AOT redesign, codegen, the `now-millis`/`i64` signedness *change* (documented,
not fixed), versioning *policy* (Story 2.4), `[allow]` (EPIC 1), Capability/TargetTriple schema
precision (2.2 follow-up).

## File structure

| File | Responsibility |

## DoD

`wit/tau-host.wit` is `package tau:host@0.1.0`; guest + host build and the guest-exec tests
pass (rename behavior-neutral); the drift test pins the 3-function surface AND breaks if a
backing port is renamed/removed/re-signatured; a reference page documents the contract; CI runs
the drift test. No new host functions; no generator; no port/WIT semantic changes.

## Risks

- **`wit-parser` API/version churn.** Pin to the version already in the lockfile (transitive via
  wit-bindgen/wasmtime) so no second copy is pulled; if its API differs, adapt the parse calls —
  the test only needs interface→functions→params/results.
- **Compile-time containment is structural, not semantic.** Referencing the port methods proves
  they *exist* with a compatible shape; it does not prove the JSON serialization of `complete`'s
  `request-json` still matches `CompletionRequest`. That deeper guarantee is the conformance
  gate's job (β.6) — noted, not in 2.3.
