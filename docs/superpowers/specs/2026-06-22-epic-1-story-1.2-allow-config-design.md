# EPIC 1 · Story 1.2 — `[allow]` config parse + round-trip (design)

**Date:** 2026-06-22
**Status:** Approved (brainstorm complete; awaiting implementation plan)
**Story:** vision-roadmap EPIC 1 · 1.2 — "Config: `[allow]` capability ceiling +
`[allow.mcp]`/`[allow.tools]`/`[allow.models]` registry. Accept: parses;
round-trips."
**Constitution:** [ADR-0057](../../decisions/0057-root-allow-governance.md)

## Purpose

Parse the root `tau.toml` `[allow]` constitution into a validated in-memory
shape and prove it round-trips. This is the first *code* story of EPIC 1; it
provides the typed `AllowConfig` that stories 1.3–1.5 enforce against. It adds
**no enforcement** — only deserialization, internal well-formedness validation,
and round-trip.

## Scope boundary

**In scope (1.2):**

- Deserialize `[allow]`, `[allow.models]`, `[allow.mcp.<name>]`,
  `[allow.tools.<name>]` into `Unchecked*` types that round-trip.
- Validate *internal well-formedness only* (see Validation rules).
- Lift into a validated `AllowConfig` on `ProjectConfig` (`Option`, opt-in).
- Round-trip tests.

**Out of scope (deferred):**

- Subset checks (`agent ⊆ root`, tool ceilings) → 1.3 / 1.5.
- Closed-world reference checks (an agent names a model/mcp/tool not
  registered) → 1.4.
- The absent-`[allow]` warning (a `tau check` surface) → 1.4.
- Wiring `AllowConfig` into runtime / lowering → later epics.

## Placement

`crates/tau-pkg/src/project/project.rs` is ~4400 lines. The new `[allow]` types
and validation go in a new sibling module
**`crates/tau-pkg/src/project/allow.rs`**, declared in `project/mod.rs`. It
exposes `UncheckedAllow`, `AllowConfig` (+ inner validated types), and
`fn validate_allow(...)`. `project.rs` stays the orchestrator: `validate()`
gains one `validate_allow` call alongside the existing `validate_tool` /
`validate_models` / etc. calls. This is a focused new file, not a refactor of
existing code.

## Deserialization types (in `allow.rs`)

All derive `Deserialize, Serialize` for round-trip.

```rust
pub struct UncheckedAllow {
    #[serde(default)] pub models: BTreeMap<String, RawModelEntry>,   // reuse existing type
    #[serde(default)] pub mcp:    BTreeMap<String, UncheckedMcpAllow>,
    #[serde(default)] pub tools:  BTreeMap<String, UncheckedToolAllow>,
    #[serde(flatten)] pub caps:   BTreeMap<String, toml::Value>,     // "fs.read" => {paths=[…]}
}

pub struct UncheckedMcpAllow {
    pub url: String,
    #[serde(default)] pub hosts: Vec<String>,
}

pub struct UncheckedToolAllow {
    #[serde(default)] pub native: Option<String>,   // native xor mcp binding
    #[serde(default)] pub mcp:    Option<String>,
    #[serde(flatten)] pub caps:   BTreeMap<String, toml::Value>,     // optional per-tool ceiling
}
```

`models` / `mcp` / `tools` bind to named fields; serde's `flatten` captures the
remaining keys as raw caps. (`#[serde(flatten)]` disables `deny_unknown_fields`,
so unknown / malformed cap kinds are rejected at validate time instead — see
Validation rules.)

On `UncheckedProjectConfig`:

```rust
#[serde(default)] pub allow: Option<UncheckedAllow>,
```

## Validated types (in `allow.rs`)

```rust
pub struct AllowConfig {
    pub ceiling: Vec<Capability>,                  // raw caps, via the serde bridge
    pub models:  BTreeMap<String, ModelEntry>,     // reuse existing validated type
    pub mcp:     BTreeMap<String, McpAllowEntry>,
    pub tools:   BTreeMap<String, ToolAllowEntry>,
}

pub struct McpAllowEntry  { pub url: String, pub hosts: Vec<String> }  // hosts derived from url if empty
pub struct ToolAllowEntry { pub binding: ToolBinding, pub ceiling: Vec<Capability> }
```

`ToolBinding` is `Native(String)` | `Mcp(String)`. On `ProjectConfig`:

```rust
pub allow: Option<AllowConfig>,   // None = no constitution declared (opt-in, ADR-0057 §5)
```

### The serialization bridge (representation decision, ADR-0057 §2)

The validated raw-cap ceiling **is** `Vec<Capability>` — the exact type the
existing subset checker (`compute_effective` / `glob_subset`) consumes — so
stories 1.3–1.5 plug in with zero conversion. `Capability` is
`#[non_exhaustive]`; it is constructed via serde, not struct literals. For each
`"fs.read" = {paths=[…]}` entry, validation re-emits `{kind:"fs.read",
paths:[…]}` and deserializes into `Capability` (the same bridge β.8 used). The
kind-as-key TOML surface stays for authoring; the canonical type is produced at
the validation boundary.

## Validation rules (`validate_allow`)

Internal well-formedness only:

1. **Raw-cap keys** limited to `fs.read`, `fs.write`, `fs.exec`, `net.http`,
   `process.spawn`. Reject `agent.spawn`, `custom`, and unknown keys with a
   clear error (agent-spawn governance flows through the lattice's spawn link,
   not a raw ceiling entry; custom is not narrowable — matches
   `compute_effective`'s existing stance).
2. **Raw-cap values** must bridge cleanly into `Capability` (value shape matches
   the kind); a bridge failure → error naming the offending kind.
3. **`[allow.mcp.x].url`** non-empty and parses as a URL; derive `hosts` from
   the url's host when `hosts` is absent.
4. **`[allow.tools.x]`** has exactly one binding (`native` xor `mcp`); its
   optional per-tool ceiling caps validate by rules 1–2.
5. **`[models]` coexistence:** if `allow` is present *and* top-level `[models]`
   is non-empty → error (`[allow.models]` is the sole home when a constitution
   is declared). When `allow` is absent, top-level `[models]` works unchanged.

## Error handling

Add one variant to the `#[non_exhaustive]` `ProjectConfigError` enum, mirroring
the existing `AgentValidation` shape:

```rust
#[error("[allow]: {message}")]
AllowValidation { message: String },
```

## Round-trip

`parse → serialize the UncheckedAllow → re-parse` yields an equal
`UncheckedAllow`. `toml::Value` plus the named `BTreeMap`s round-trip
structurally. Equality follows whatever the existing project round-trip tests
use (value/structural equality, not necessarily byte-identical TOML, since
`BTreeMap` ordering is canonicalised).

## Testing (TDD)

Unit tests in `allow.rs` + at least one integration fixture under the
project-config test suite:

- Well-formed full `[allow]` (raw caps + models + mcp + tools) parses.
- Round-trip equality on that config.
- Deny-by-kind: `agent.spawn` / `custom` / unknown raw-cap key rejected.
- Malformed cap shape (e.g. `net.http` with `paths`) rejected.
- MCP `url` present → `hosts` derived; explicit `hosts` preserved; empty/invalid
  url rejected.
- Tool single-binding: both `native` and `mcp` → error; neither → error.
- `[models]` + `[allow]` both present → conflict error; `[allow.models]` alone
  validates.
- Absent `[allow]` → `ProjectConfig.allow == None` and legacy top-level
  `[models]` still validates (opt-in preserved).
