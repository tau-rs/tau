# EPIC 1 · Story 1.4 — `tau check` governance enforcement (design)

**Date:** 2026-06-22
**Status:** Approved (brainstorm complete; awaiting implementation plan)
**Story:** vision-roadmap EPIC 1 · 1.4 — "`tau check` fails if any agent/tool/region
cap ⊄ `[allow]` or references an unregistered resource. Accept: over-reaching
fixture fails with a clear error."
**Constitution:** [ADR-0057](../../decisions/0057-root-allow-governance.md).
**Consumes:** 1.2 `AllowConfig` (`ProjectConfig.allow`), 1.3
`capability_set_subset` (`tau_pkg::capability_override`).

## Purpose

Make the root `[allow]` constitution *bite* at build time: `tau check` fails
when a tool/agent capability declared in `tau.toml` exceeds the root ceiling, or
when an agent/tool references a model/mcp/tool that is not registered in
`[allow.*]`. This is EPIC 1's first enforcement story — 1.1–1.3 built the ADR,
the config, and the subset primitive; 1.4 wires them into `tau check`.

## Scope (the 1.4 ↔ 1.5 cut)

1.4 = **everything fits under the ROOT ceiling + closed-world references**
(checks against `[allow]` directly). 1.5 = the **relative** lattice links
(`agent ⊇ spawn ⊇ tool` — child vs *enclosing* level). They share
`capability_set_subset` but feed it different parents, so no code overlap.

## Capability source (Option A — manifest-free)

1.4 checks only capabilities **declared in `tau.toml`** — it does NOT load
package manifests. The agent-via-package *effective* caps check
(package ∩ override ⊆ root) requires manifest resolution and is **deferred**
(tracked below). This keeps 1.4 self-contained and order-independent in
`tau check`.

## New `tau check` category

A new category `Governance`, following the existing pattern exactly:

- `crates/tau-cli/src/cmd/check/result.rs` — add `CheckCategory::Governance`
  variant + its `name()` arm (`"governance"`).
- `crates/tau-cli/src/cmd/check/categories/governance.rs` — **new file** —
  `pub fn run_governance(ctx: &CheckCtx) -> CheckResult` (sync, like
  `run_config`/`run_packages`).
- `crates/tau-cli/src/cmd/check/categories/mod.rs` — `pub mod governance;`.
- `crates/tau-cli/src/cmd/check/runner.rs` — add the match arm in `run_one`
  and include `Governance` in the default category list.

No EPIC 2.2 (#432) overlap — that PR does not touch `tau check`.

## Opt-in handling (ADR-0057 §5)

- `ctx.project` is `None` (malformed/absent tau.toml) → `CheckStatus::Skipped`
  (the `config` category already reports the parse error).
- `project.allow == None` → a single `Severity::Warning` finding: "no `[allow]`
  constitution declared; governance not enforced." Exit stays 0 (a nudge, not a
  failure — `compute_exit` ignores `Warning`).
- `project.allow == Some(allow)` → run the checks below. Every violation is a
  `Severity::Error` finding → `compute_exit` returns 2.

## Checks (when `allow` is present)

### Over-reach (child ⊆ `allow.ceiling`, via `capability_set_subset`)

1. **Tool definitions:** for each `(name, tool)` in `project.tools`,
   `capability_set_subset(&tool.capabilities, &allow.ceiling)`. On
   `Err(violation)` → Error: `tool '<name>': capability <kind> "<offender>"
   exceeds [allow] ceiling`.
2. **Registered tool ceilings:** for each `(name, entry)` in `allow.tools`,
   `capability_set_subset(&entry.ceiling, &allow.ceiling)`. On Err → Error:
   `[allow.tools.<name>] ceiling <kind> "<offender>" exceeds [allow] ceiling`.
3. **Agent overrides (manifest-free, partial):** for each agent in
   `project.agents`, for each `CapabilityOverride` in
   `agent.capability_overrides` whose `allow` is `Some(list)`: synthesize a
   `Capability` from `(kind, list)` and run
   `capability_set_subset(&[synth], &allow.ceiling)`. On Err → Error:
   `agent '<id>': override <kind> "<offender>" exceeds [allow] ceiling`.
   Overrides with `allow: None` ("use the package's field") are NOT checked here
   — that needs the manifest (deferred). `deny`/`max_bytes` only narrow, so they
   are not over-reach concerns.

**Synthesizing a `Capability` from an override** (check 3): `Capability` is
`#[non_exhaustive]` and constructed via serde. Build a `serde_json::Value`
`{ "kind": <kind>, <field>: <list> }` where `<field>` is `paths` for
`fs.read`/`fs.write`/`fs.exec`, `hosts` for `net.http`, `commands` for
`process.spawn`; `serde_json::from_value::<Capability>(...)`. Override kinds
outside that set (the override layer only emits these five) are skipped.

### Closed-world references (registry is authoritative)

4. **Agent model:** for each agent with non-empty `model`, require
   `allow.models.contains_key(&model)`. Else Error: `agent '<id>' references
   unregistered model '<model>' — add [allow.models.<model>]`.
5. **Agent tool refs:** for each agent, for each `name` in `tool_refs`, require
   `allow.tools.contains_key(name)`. Else Error: `agent '<id>' references
   unregistered tool '<name>' — add [allow.tools.<name>]`.
6. **Tool definitions registered:** for each `name` in `project.tools`, require
   `allow.tools.contains_key(name)`. Else Error: `tool '<name>' is defined but
   not registered in [allow.tools]`.
7. **Tool→MCP bindings:** for each `(name, entry)` in `allow.tools` whose
   `binding` is `ToolBinding::Mcp(mcp_name)`, require
   `allow.mcp.contains_key(&mcp_name)`. Else Error: `[allow.tools.<name>] binds
   MCP '<mcp_name>' which is not registered in [allow.mcp]`.

## Finding shape

`CheckFinding { category: CheckCategory::Governance, severity, message,
location: Some(FindingLocation { path: tau.toml, .. }), structured }`. `message`
names the exact offender (from `CeilingViolation.offender` or the unregistered
name). `structured` carries a JSON object (`{ "check": "...", "kind": "...",
"offender": "...", "subject": "<agent|tool name>" }`) for `--json` / SARIF
output. Findings are accumulated (all violations reported, not first-only) so
the author sees every problem in one run.

## Testing (integration, fixture `tau.toml`s under the check test suite)

- Over-reaching `[tools.x].capabilities` (e.g. `fs.read=["/etc/**"]` under root
  `/proj/**`) → Error, message names `/etc/**`, exit 2.
- Over-reaching agent override → Error naming the offending entry.
- `[allow.tools.x]` ceiling exceeding root → Error.
- Agent references unregistered `model` / `tool` → Error each.
- `[tools.x]` defined but absent from `[allow.tools]` → Error.
- `[allow.tools.x]` binds an MCP absent from `[allow.mcp]` → Error.
- A fully within-ceiling, fully-registered fixture → no Error findings, exit 0.
- No `[allow]` block → exactly one `Warning` finding, exit 0.
- Exit-code assertion: an over-reaching fixture yields `compute_exit == 2`.

## Out of scope (deferred, tracked)

- **Package-manifest effective caps** (agent's package ∩ override ⊆ root) —
  needs manifest resolution in `CheckCtx`; a follow-up once that plumbing
  exists.
- The **relative** `agent ⊇ spawn ⊇ tool` lattice links → Story 1.5.
- The **coarse-ceiling lint** (`hosts=["*"]` etc.) → Story 1.6.
- Dynamic-region links → EPIC 4 (per ADR-0057).

## Crates touched

`tau-cli` only (`cmd/check/categories/governance.rs` new; `cmd/check/{result,
runner}.rs` + `categories/mod.rs` edited). No `tau-pkg` change — it already
exposes `AllowConfig` and `capability_set_subset`.
