# EPIC 4.1 — IR structured control-flow blocks (the IR bump) — design

**Date:** 2026-06-22
**Status:** Proposed — pending review
**Epic:** 4 — IR control flow: structured blocks + dynamic regions  [needs 2; done]
**Story:** 4.1 (ADR + IR bump: `StepRun` gains Branch/Parallel/Loop/Suspend; reuse
`Locus`/`GoalPredicate`/`OnFail::Retry`; byte-stable when unused).
**Anchors:** ADR-0037 (workflow IR), ADR-0044 (deliverables & goals — `Locus`/`GoalPredicate`),
ADR-0053 (`per_tool_call` checkpoint, reused by Suspend in 4.3), ADR-0056 (IR is a versioned
contract). Pairs with the published IR JSON schema (#430).

## Problem & scope

The IR's `Pipeline` is a flat top-to-bottom list of `PipelineStep`s whose `run: StepRun` is one
of four **leaf** operations (`Agent`/`Tool`/`Deterministic`/`Check`). Real workflows need
**structured control flow**: conditional branches, parallel fork-join, bounded loops, and
human-in-the-loop suspend/resume. EPIC 4 adds these; **4.1 is the foundational IR-data-model +
contract change only.**

**In scope (4.1):** add the 4 structured-block variants to `StepRun` (making it recursive); a
reused `Condition` type; typecheck of the nested steps; regenerate + version the published IR
JSON schema; a byte-stability proof; the ADR. **Out (later stories):** the interpreter that
*executes* the blocks (4.2), Suspend's checkpoint/resume round-trip (4.3), `StepRun::Dynamic`
capability-bounded regions (4.4–4.5), conformance (4.6), and lowering these from `tau.toml`
(folds into 4.2's usability work). 4.1 makes the IR *able to express* the blocks, byte-stable
and contract-versioned, without yet running them.

## Decision

### 1. `StepRun` gains four recursive variants (appended — byte-stable)

`crates/tau-ir/src/pipeline.rs`, append to `StepRun` (existing four leaves unchanged):

```rust
pub enum StepRun {
    Agent(AgentId),
    Tool(ToolId),
    Deterministic(StepId),
    Check(CheckId),

    // --- EPIC 4.1: structured control-flow blocks (recursive) ---

    /// Run `then` if `on` holds, else `otherwise` (which may be empty).
    Branch {
        on: Condition,
        then: Vec<PipelineStep>,
        otherwise: Vec<PipelineStep>,
    },
    /// Fork the branches, run them concurrently, join. Bounded fork-join
    /// (the interpreter caps concurrency — 4.2).
    Parallel {
        branches: Vec<Vec<PipelineStep>>,
    },
    /// Run `body` repeatedly until `until` holds or `max_iters` is reached
    /// (mandatory bound — no unbounded loops). Reuses the `OnFail::Retry`
    /// rewind machinery in the interpreter (4.2).
    Loop {
        body: Vec<PipelineStep>,
        until: Condition,
        max_iters: u64,
    },
    /// Human-in-the-loop pause: checkpoint and wait for `resume_signal`,
    /// then seed-and-skip resume (reuses the ADR-0053 `per_tool_call`
    /// checkpoint; the round-trip lands in 4.3).
    Suspend {
        resume_signal: String,
    },
}
```

`StepRun` becoming recursive (variants holding `Vec<PipelineStep>`) is the core change.
`PipelineStep`/`Pipeline` are unchanged.

### 2. A reused `Condition` (DRY with `CheckVerify::Goal`)

Branch and Loop need a deterministic condition. `CheckVerify::Goal { evaluates: Locus,
predicate: GoalPredicate }` already *is* that shape. Extract it into a named, reusable type in
`crates/tau-ir/src/check.rs`:

```rust
/// A deterministic predicate over a read locus — the condition for a
/// `Branch`/`Loop` and the goal arm of a `Check`.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[cfg_attr(feature = "schema", derive(schemars::JsonSchema))]
pub struct Condition {
    pub evaluates: Locus,
    pub predicate: GoalPredicate,
}
```

`CheckVerify::Goal` is refactored to hold a `Condition` (its `{ evaluates, predicate }` fields
move into `Condition`) — a **structural refactor that must preserve the serde wire form** so
existing IR stays byte-identical (verified by the existing canonical round-trip tests +
the byte-stability test below). If preserving the exact `Goal { evaluates, predicate }` JSON
shape while nesting a `Condition` proves to require `#[serde(flatten)]` (which changes nothing
on the wire), use it; if it risks any wire change, keep `Condition` as a standalone type used
only by Branch/Loop and leave `CheckVerify::Goal`'s inline fields untouched (less DRY, zero
wire risk). **Default to the zero-wire-risk option** — the byte-stability invariant outranks DRY.

### 3. Versioning + byte-stability

- `ir_format` `CURRENT`: `"v2.3.0"` → **`"v2.4.0"`** (MINOR — additive variants, forward-compatible).
- **Byte-stable when unused:** the canonical encoder (`to_canonical_bytes`) is pure serde over
  `serde_json` (BTreeMap-keyed, deterministic). Appended enum variants do not change the
  serialization of existing variants, so any IR using only the original four `StepRun` leaves
  serializes byte-identically. Proof: a test that builds a pre-4.1 module and asserts its
  canonical bytes equal a committed golden (and that `from_canonical_bytes` still round-trips).
  The existing `canonical.rs` round-trip tests already exercise the leaves; add one explicit
  byte-stability assertion + round-trips for each new variant.

### 4. Typecheck (`tau-ir-lower`)

The lowering/typecheck stage validates references. Extend it to recurse into the nested
`Vec<PipelineStep>` of Branch/Parallel/Loop: every nested step's referenced node id
(`Agent`/`Tool`/`Deterministic`/`Check`) must exist; nested `PipelineStepId`s are unique within
their scope; `Loop.max_iters > 0`; a `Condition`'s `Locus::Output` references an in-scope step.
(Executing them is 4.2; *validating their shape* is 4.1, so a malformed control-flow IR fails at
build time per the Rust-class-discipline principle.)

### 5. Published-contract regeneration (consequence of the IR change)

The IR JSON schema (#430) is generated from these serde types, so adding the variants changes
it. Run `cargo xtask gen-ir-schema` to regenerate `schema/ir/tau-ir.schema.json` (now carrying
`v2.4.0` + the Branch/Parallel/Loop/Suspend/Condition definitions); the schema drift test +
conformance samples update accordingly (add a sample exercising a Branch). This is the
additive, minor-version contract bump in action.

### 6. ADR

A new ADR (next free number — latest is ADR-0057): *IR structured control-flow blocks.* Records
the recursive-`StepRun` decision, the reuse of `Locus`/`GoalPredicate` via `Condition`, the
`OnFail::Retry` rewind reuse for `Loop`, the `max_iters` mandatory bound, the Suspend↔
`per_tool_call` checkpoint link, and the additive `ir_format` bump. Status Accepted.

## DoD

`StepRun` expresses Branch/Parallel/Loop/Suspend; `ir_format` is `v2.4.0`; **byte-stable when
unused** (golden + round-trip tests pass); typecheck validates nested control-flow shape + bounds
at build time; the published IR schema is regenerated + drift-green with a Branch sample; the ADR
is Accepted. No interpreter execution (4.2), no Suspend round-trip (4.3), no Dynamic regions (4.4).

## Risks

- **The `CheckVerify::Goal` refactor risking the wire form** — mitigated by defaulting to the
  zero-wire-risk standalone-`Condition` option (§2) and the byte-stability test gating it.
- **schemars handling the new recursive enum variants / `Vec<PipelineStep>` self-reference** —
  the 2.2 conformance test (samples validate against the regenerated schema) is the gate; if a
  recursive `$ref` mis-encodes, fix via `#[schemars(...)]` (same playbook as 2.2).
- **Adding variants is a contract change** — it is additive (minor), but it DOES bump the
  published schema; the drift/conformance tests force the regeneration to be deliberate.
