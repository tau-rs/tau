# EPIC 7.1 — no_std lib (Variant B) embedding API + worked example

**Status:** design
**Date:** 2026-08-21
**Deps:** 5.1 (`tau build --target rust-lib`, #606), 5.2 (`tau embed --host rust`, #611)
**Roadmap:** story 7.1 — "no_std lib (Variant B) embedding API + example (product links tau, impls ports)."

## Problem

5.1 emits a `#![no_std]` rust-lib crate (`TAU_IR` const + `pub use run_ir`).
5.2 emits a native host that decodes `TAU_IR` and calls `run_ir`, but its
`StubDispatcher::invoke` / `llm_backend_for` are `todo!("EPIC 7.1")` and it
inherits `clock()`/`random()` → `None`, which **panics** in a non-`test-fixtures`
build ("host shell must supply a clock"). Both 5.1 and 5.2 are *string-checked
only* (drift tests assert generated source contains `run_ir(`); neither compiles
or runs. 7.1 ships the first embedding that **compiles and runs in CI**: a real
`ToolDispatcher`, a real LLM-backend port, real `clock`/`random` ports — the
honest "product links tau, impls ports" story that 5.1/5.2 defer to.

## Chosen shape (approved)

**A committed `examples/embed-native/` workspace consisting of two crates**, both
added to the root `[workspace].members` so `cargo nextest` covers them with no
bespoke CI step:

```
examples/embed-native/
├── README.md                 # how a product links tau as a no_std lib (Variant B)
├── workflow.tau              # committed source: 1 agent, 1 tool
├── workflow-lib/             # the 5.1 rust-lib artifact (GENERATED, then committed)
│   ├── Cargo.toml            #   path-deps tau-runtime-core (default-features=false)
│   └── src/lib.rs            #   pub const TAU_IR / TAU_IR_HASH / pub use run_ir
└── host/                     # the Variant-B product (native, std)
    ├── Cargo.toml            #   path-deps workflow-lib + tau-ports + tau-runtime-core + tokio
    ├── src/
    │   ├── main.rs           #   decode TAU_IR → run_ir → print RunOutcome (cargo run)
    │   ├── lib.rs            #   re-exports dispatcher/llm/ports so tests/ can use them
    │   ├── dispatcher.rs     #   HostDispatcher: real ToolDispatcher
    │   ├── llm.rs            #   ScriptedLlmBackend: impl tau_ports::LlmBackend (CI-deterministic)
    │   └── ports.rs          #   SystemClock (std) + HostRandom (time-seeded xorshift)
    └── tests/
        └── runs.rs           #   #[tokio::test] asserting RunOutcome::Completed
```

Rejected: integration test (satisfies "runs in CI" but is not a product a reader
copies) and doctest (async + tokio + committed-lib dep fight doctest ergonomics).
Both also fail to demonstrate the two-crate link that *is* Variant B.

## Components

### `workflow.tau` (committed source)
One agent `assistant` (backend alias resolving to package `scripted`, model id
any), one tool `echo`. Agent budget `max_turns >= 2` so the scripted 2-turn run
(tool call → final text) completes rather than truncating.

### `workflow-lib/` (the 5.1 artifact)
Generated by `tau build --target rust-lib -o examples/embed-native/workflow-lib`
from `workflow.tau`, then its `Cargo.toml` deps hand-patched from published
`version = "…"` form to in-repo `path = "…"` form (tau is unpublished; workspace
members need path deps). `src/lib.rs` is committed **verbatim as generated** —
never hand-edited — so the drift test can byte-compare it. README documents the
regenerate-then-repatch step.

### `host/` (the Variant-B product)
Mirrors the structure of `crates/tau-runtime-tokio/tests/ir_smoke.rs` (closest
existing `build-a-dispatcher-and-call-run_ir` reference), but as a *product* with
real port bodies and **zero test-only deps**:

- **`ScriptedLlmBackend`** (`llm.rs`) — `impl tau_ports::LlmBackend`. FIFO script
  of turns; `complete()` pops one turn, `stream()` uses the public
  `tau_ports::batch_to_stream` helper. Turn 1 → `CompletionResponse { text: "",
  tool_uses: vec![ToolUse::new(id, "echo", {"text":"hello"})], stop_reason:
  ToolUse, .. }`; turn 2 → `{ text: "done", tool_uses: [], stop_reason: EndTurn }`.
  Any `LlmBackend` auto-becomes `DynLlmBackend` via the blanket impl in
  `tau_runtime_core::builder`. This is the "product implements the LLM port"
  demonstration and gives CI determinism without `tau-ports/test-fixtures`.
- **`HostDispatcher`** (`dispatcher.rs`) — `impl ToolDispatcher`:
  - `invoke(tool_id, args)` — matches `tool_id` and really executes `echo`
    (returns `ToolInvocationResult { body: Some({"echoed": <text>}), error: None }`);
    unknown tool → `RuntimeError`.
  - `llm_backend_for(backend)` — returns the `Arc<ScriptedLlmBackend>`.
  - `clock()` — `Some(Arc::new(SystemClock))` (real port; closes the panic gap).
  - `random()` — `Some(Arc::new(HostRandom::new()))` (real port).
- **`ports.rs`** — `SystemClock` (`Clock::now` via
  `SystemTime::now().duration_since(UNIX_EPOCH)` → `i64` ms) and `HostRandom`
  (`RandomSource::fill` via a time-seeded xorshift; documented as non-crypto,
  with a comment pointing real products at `getrandom`/OS entropy). Zero deps.
- **`main.rs`** — `let module = Arc::new(from_canonical_bytes(TAU_IR)?); let entry
  = module.workflow.agents.keys().next().expect(..).clone(); let outcome =
  run_ir(module, &entry, Arc::new(HostDispatcher::new()), Vec::new()).await?;`
  then pretty-prints `outcome` and exits nonzero on `RunOutcome::Failed`.

### `host/tests/runs.rs`
`#[tokio::test]` builds the same dispatcher, runs `run_ir`, asserts
`RunOutcome::Completed { total_turns, final_message, .. }` with `total_turns == 2`
and `final_message` text `== "done"`. Asserts only LLM-driven fields — never
clock/random-derived session ids/timestamps — so it is deterministic under real
`SystemClock`/`HostRandom`.

## Data flow

```
workflow.tau ──tau build──▶ workflow-lib/src/lib.rs (TAU_IR: &[u8], canonical serde_json)
                                     │ pub use run_ir
host ── from_canonical_bytes(TAU_IR) ─▶ Arc<IrModule>
     ── run_ir(module, entry, HostDispatcher, []) ──▶ agent loop
            ├─ turn 1: ScriptedLlmBackend → ToolUse("echo") → HostDispatcher.invoke → {"echoed":…}
            └─ turn 2: ScriptedLlmBackend → Text("done"), EndTurn
     ◀── RunOutcome::Completed { total_turns: 2, final_message: "done", .. }
```

## Drift guard

`crates/tau-cli/tests/embed_native_example.rs` (mirrors the existing
`embed_hosts.rs` drift-proof pattern): runs the built `tau` binary
(`tau build --target rust-lib -o <tmpdir>`) on the committed `workflow.tau`, then
asserts the freshly-emitted `src/lib.rs` **byte-equals** the committed
`workflow-lib/src/lib.rs`. This keeps `TAU_IR`/`TAU_IR_HASH` honest as the IR
format evolves; it ignores `Cargo.toml` (which is intentionally path-patched).
If shelling to the binary proves slow/flaky in the plan phase, fall back to
comparing via `tau_sdk_codegen::render_rust_lib` fed the same lowered IR bytes.

## Error handling

- Decode failure (`from_canonical_bytes`) → `IrError` propagated from `main`
  (`Result<(), Box<dyn Error>>`); the test never hits it (committed IR is valid).
- Unknown tool id in `invoke` → `RuntimeError::Internal`, surfaces as
  `RunOutcome::Failed` (not asserted in the happy path; a second negative test may
  assert an unknown-tool workflow fails cleanly — optional, decide in plan).
- Missing entry agent is impossible (committed IR has ≥1 agent); no guard needed
  beyond the `.expect` the 5.2 scaffold already uses.

## Testing

- `host/tests/runs.rs` — happy-path `RunOutcome::Completed` (nextest).
- `crates/tau-cli/tests/embed_native_example.rs` — lib drift guard (nextest).
- `cargo run -p embed-native-host` — manual smoke (documented in README).
- Both example crates compile under `cargo build --workspace` (CI Tier 0).

## Known limitations (explicit, not solved here)

- **Workspace feature unification** means that when `host` (std + tokio) and
  `workflow-lib` (`default-features=false`) build together, `tau-runtime-core`
  gets std features unified on. The workspace build therefore proves the
  embedding API *links and runs*, but does **not** prove a true bare-metal
  `no_std` compile. A target-isolated `no_std` build job is out of scope for 7.1
  (belongs with 7.3/7.4 MCU work) and is noted in the README.
- `HostRandom` is non-cryptographic (time-seeded xorshift) to stay dependency-
  free; the README directs real products to `getrandom`/OS entropy. The example's
  correctness does not depend on entropy quality (no asserted field is random-
  derived).
