# IR JSON schema

The IR JSON schema is tau's **authoring/IR contract** — one of the two
public contracts defined in
[ADR-0055](../decisions/0055-tau-identity-two-contracts.md) and versioned in
[ADR-0056](../decisions/0056-contract-versioning-stability-surface.md).

The schema describes every `IrModule` that tau's lowering pipeline can
emit and that any compliant host must accept. Frontend tools, SDK
wrappers, and third-party IR generators should validate their output
against it before shipping.

## Location

The schema and conformance kit live under `schema/ir/` in the tau
repository:

| File | Purpose |
|---|---|
| [`schema/ir/tau-ir.schema.json`](https://github.com/tau-rs/tau/blob/main/schema/ir/tau-ir.schema.json) | The published JSON Schema (Draft 7) |
| [`schema/ir/samples/`](https://github.com/tau-rs/tau/blob/main/schema/ir/samples/) | Valid IR samples (one per node category) |
| [`schema/ir/README.md`](https://github.com/tau-rs/tau/blob/main/schema/ir/README.md) | Kit overview and regeneration instructions |

## Versioning

The schema version tracks `ir_format` (the `IrFormatVersion` constant in
`tau-ir`). The current version is embedded in the schema's `title` and
`$id` fields. Bumping `IrFormatVersion::CURRENT` regenerates the schema
and bumps the `$id`.

Stability guarantees follow ADR-0056: the IR contract is a semver
stability surface. Additive changes are non-breaking; field removals or
semantic changes require a major version bump.

## How to validate

Use any Draft-7-compatible JSON Schema validator. The schema's `$schema`
field identifies the exact draft:

```rust
// Rust — jsonschema crate
let schema = serde_json::from_slice(include_bytes!("tau-ir.schema.json"))?;
let v = jsonschema::options()
    .with_draft(jsonschema::Draft::Draft7)
    .build(&schema)?;
assert!(v.is_valid(&your_ir_json));
```

```python
# Python — jsonschema package
import json, jsonschema
schema = json.load(open("tau-ir.schema.json"))
jsonschema.validate(instance=your_ir, schema=schema)
```

```js
// JavaScript — ajv
import Ajv from "ajv";
import schema from "./tau-ir.schema.json" assert { type: "json" };
const ajv = new Ajv({ strict: false });
const validate = ajv.compile(schema);
assert(validate(yourIr));
```

## Conformance kit samples

`schema/ir/samples/` contains five valid `IrModule` instances, one per
major node category. They are regenerated by `cargo xtask gen-ir-schema`
and validated against the schema in CI.

| Sample file | Exercises |
|---|---|
| [`agent_native_tool.json`](https://github.com/tau-rs/tau/blob/main/schema/ir/samples/agent_native_tool.json) | Agent node wired to a native (non-MCP) tool |
| [`agent_mcp_tool.json`](https://github.com/tau-rs/tau/blob/main/schema/ir/samples/agent_mcp_tool.json) | Agent node wired to an MCP tool |
| [`deterministic_step.json`](https://github.com/tau-rs/tau/blob/main/schema/ir/samples/deterministic_step.json) | Standalone deterministic step node |
| [`subflow.json`](https://github.com/tau-rs/tau/blob/main/schema/ir/samples/subflow.json) | Subflow node (nested `IrModule`) |
| [`tool_impl_step.json`](https://github.com/tau-rs/tau/blob/main/schema/ir/samples/tool_impl_step.json) | Tool whose `impl` is a deterministic `Step` |

## Regenerating (maintainers)

```
cargo xtask gen-ir-schema
```

This runs the `schema_drift` test in bless mode, which rewrites
`schema/ir/tau-ir.schema.json` and `schema/ir/samples/*.json` from the
live `tau-ir` Rust types. The drift test in CI then detects any
uncommitted divergence.
