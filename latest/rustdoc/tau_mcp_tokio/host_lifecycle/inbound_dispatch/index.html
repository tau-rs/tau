Inbound-dispatch task for McpClient.

PR-3 shipped McpClient with outbound-only call_tool semantics: the inbound side of transport.next_message() was drained ad-hoc by call_tool’s response loop. PR-5 adds the server-initiated request side: a tokio task that loops on transport.next_message, routes sampling/createMessage + roots/list requests through HostHandlers, and writes responses back via transport.send_message.

Cancellation propagation (PR-5.1) is NOT in this PR — the pump exits cleanly when the transport closes (next_message returns None or McpError::Transport), and the parent can shutdown() the handle to abort the task.
