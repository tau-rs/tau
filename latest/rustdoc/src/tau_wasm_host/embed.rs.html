1//! Curated Variant A embedding surface (EPIC 7.2).
2//!
3//! A product embeds tau by (1) building a component (`tau build --target
4//! wasm`), (2) implementing [`EmbedPorts`] — live inference, wall clock,
5//! entropy, and a live [`on_event`](EmbedPorts::on_event) sink — and
6//! (3) calling [`run_component_with_ports`]. Capabilities granted to the
7//! component ([`Capability`]) are enforced at the wasm boundary: fs/net the
8//! caps don't grant is physically unreachable from the workflow.
9//!
10//! This module re-exports [`Capability`] so the type is nameable, but not
11//! a way to construct a non-empty one: `Capability`'s variants are
12//! per-variant `#[non_exhaustive]`, and the builder helpers live behind
13//! tau-domain's test-only `test-fixtures` feature. Today the supported way
14//! to obtain a real `caps` slice is deserializing it from a package
15//! manifest via `tau-pkg` (the same manifest `tau build` reads). The
16//! shipped reference host (`crates/tau-wasm-embed-example`) grants none —
17//! it calls [`run_component_with_ports`] with `&[]`, so the workflow gets no
18//! fs/net regardless of what it asks for.
19//!
20//! Everything here is a re-export: this module pins *which* items form the
21//! supported embedding API, mirroring `tau_runtime_core::embed` (Variant B,
22//! EPIC 7.1). See `docs/how-to/embed-wasm-component.md` for the worked
23//! example (`crates/tau-wasm-embed-example`). The deterministic conformance
24//! entrypoints (`run_component`, `run_component_with_caps`) stay at the
25//! crate root — they are not part of the embedding surface.
26
27pub use crate::{run_component_with_ports, EmbedPorts, WasmHostError};
28pub use tau_domain::Capability;
29pub use tau_ports::llm::{CompletionRequest, CompletionResponse, StopReason, TokenUsage, ToolUse};
