Expand description

Capability declarations attached to a package manifest.

Hierarchical typed enum: top-level by namespace (Filesystem/Network/Process/Agent/Custom), per-namespace verb enums underneath. Variant-level #[non_exhaustive] permits additive field evolution.

Wire format per ADR-0002: manifest TOML uses flat dot-namespaced kind = "fs.read" form. The custom Deserialize impl on Capability maps it onto the variant tree.

Structs§

CapabilityShapeSet
A set of CapabilityShapes, used by adapters to declare what they support and by the runtime to declare what a plan requires. Subset / membership queries are O(n) where n is the set size; we expect at most ~6 entries.

VocabMode
Whether unknown (non-custom.) capability kinds are accepted during deserialization. Authoring surfaces (tau.toml, [allow]) and interchange readers use VocabMode::Strict; a package manifest declaring a vocab_version newer than KNOWN_VOCAB uses VocabMode::Vocab, which admits unknown kinds as Capability::Forward instead of erroring (D7-B PR2).

Constants§

KNOWN_VOCAB
The capability-vocabulary generation this build of tau understands. A manifest may declare a vocab_version newer than this to opt unknown kinds into forward-compatible Capability::Forward parsing. Bump this when a kind graduates from Forward to a typed variant.
