&str flavor of normalize_crlf_bytes, with identical semantics.

Used by the [dirs] definition-file parsers, which work on text (frontmatter + markdown body) rather than raw bytes. Normalizing is UTF-8-preserving: \r and \n are ASCII and can never appear inside a multi-byte code point.

§Example

use tau_pkg::crlf::normalize_crlf_str;

assert_eq!(normalize_crlf_str("a\r\r\nb"), "a\nb");
assert_eq!(normalize_crlf_str(&normalize_crlf_str("a\r\r\nb")), "a\nb");
